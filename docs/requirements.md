# 요구사항

공유형 개인 비서 & 대시보드의 요구사항과 구현 상태. 원본은 설계 문서 「공유형 개인 비서 & 대시보드 — 아키텍처 및 계획」이고,
그 뒤 사용자 요청으로 바뀐 부분을 여기에 반영한다. **요구사항이 바뀌면 이 문서를 먼저 고치고**, 화면 문구는
`web/src/components/HelpPage.tsx`, 바뀐 이력은 [CHANGELOG.md](CHANGELOG.md)에 남긴다.

- 기준 버전: 0.2.3 (2026-10-11)
- 상태: ✅ 구현·테스트됨 · 🟡 일부 · ⬜ 아직

## 1. 범위

N명(가족·동거인 규모, 수~십 명)이 한 서버를 공유한다. 일정 유형은 개인 루틴, 공과금, 대출 상환, 갱신·만기 등
"기록 기반으로 예측 가능한 할 일"이다. 일반 캘린더 앱(회의 초대, 실시간 공유 편집)은 대체하지 않는다.

핵심 원칙: **LLM은 읽고 구조화만, 날짜 계산은 코드가 한다.** 노트가 원본이고 DB는 노트에서 다시 만들 수 있는 인덱스다.

## 4. 화면 요구사항

화면별 버튼과 동작은 사용자용 도움말(`#/help`)이 기준이다. 요약:

| 화면 | 주소 | 내용 |
|---|---|---|
| 전체 보기 | `#/` (보기=전체) | 사람 카드(연체·오늘·다음 N일·확인 필요), 이번 달 납부 예정, 사람 색 점 달력, 사람별 상위 5건(✓ 완료) |
| 개인 보기 · 일정 | `#/` (보기=개인, 탭=일정) | 배지, 항목 이름 달력(허용 구간 띠), 다음 N일 전체 목록(완료·미루기·날짜 변경·건너뛰기), 확인 필요, 이번 달 납부 |
| 개인 보기 · 노트 | `#/` (탭=노트) | Markdown 편집기(이력 줄 회색), 섹션별 분석 카드, 항목 추가·되돌리기·저장·다시 분석 |
| 날짜 상세 | 달력 날짜 누르기 | 해야 할 일 / 허용 구간에 걸친 일 / 한 일, 지난 날 "이날 완료로 기록" |
| 항목 상세 | 제목 누르기 | 규칙, 중요도 변경, 알림, 근거 문장, 이력, 노트 미리보기, 노트 열기 |
| 사람 관리 | `#/people` | 추가(이름·색), 이름·색 저장, 일정·노트 바로가기, 삭제(확인 후, 노트는 `_archive`로) |
| 도움말 | `#/help` | 모든 버튼 설명, 노트 쓰는 법, 배지 의미, LLM 불 |
| 상단 바 | 모든 화면 | 전체/개인 보기, 사람 선택, 다음 7/14/30일, LLM 불, 사람 관리, 도움말, 테마(라이트→다크→시스템, 기본 라이트) |

상태 배지 규칙: 알약형이 아닌 모서리 4px, 위아래 여백 최소, 글자 세로 가운데. 색은 연체=위험, 오늘=경고,
확인 필요=강조, 나머지 회색. 사람 색과 겹치지 않는다. 중요도는 색이 아니라 기호(▲●▽)와 굵기로.

## 5. 단계별 수용 기준

| 단계 | 기준 | 상태 |
|---|---|---|
| Phase 0 | 평가셋 30~50개, 정확도 90% 이상 모델+프롬프트, 운영 LLM 위치 결정 | 🟡 평가셋 24개에서 gemma3:4b + 프롬프트 v2가 23/24(96%, 개발 노트북). 평가셋 확대, 7B·14B 비교, 운영 위치 결정은 남음 |
| Phase 1 | 머리 자르기 시나리오 처음부터 끝까지, macOS에서도 같은 테스트 통과 | 🟡 Windows 통과, macOS 미실행 |
| Phase 2 | 태블릿 2명 이상 2주 실사용, 놓친 일정 0건, LLM 노드 하나 꺼도 정상 | 🟡 기능 구현, 실사용 전 |
| Phase 3 | 한 달치 공과금·상환 일정이 실제 납부일과 일치 | 🟡 기능 구현, 실데이터 검증 전 |
| Phase 4 | learned 주기, 주기 제안, PWA, 달력 드래그, ICS 내보내기 | 🟡 앞의 셋만 |
| Phase 5 | Capacitor 앱이 같은 `/api/v1`로 동작 | ⬜ |

## 6. 열린 질문과 지금의 임시 결정

| 질문 | 임시 결정 (코드에 반영된 것) |
|---|---|
| 운영 LLM 위치(Mac mini 단독 vs Windows PC 병행) | 둘 다 `LLM_ENDPOINTS`에 순서대로. Phase 0 결과로 정한다 |
| 노트 편집 위치(앱만 vs 외부 편집기 허용) | 둘 다 허용. 파일 감시 + 3-way 병합 |
| 공동 항목은 누구 노트에, 완료는 누가 | 한 사람 노트에 `(공동: 이름)`. 담당자 누구든 완료 가능 |
| 사람 이름을 바꾸면 공동 줄은 | 앱이 고치지 않고 고쳐야 할 줄을 알려 준다 |
| 사람을 지우면 노트는 | 지우지 않고 `people/_archive/<id>-<시각>/`로 옮긴다. 마지막 1명은 못 지운다 |
| 다른 사람의 일정을 볼 권한 | 모두가 모두를 본다(기기 토큰은 사람이 아니라 기기 단위) |
| 알림 채널 | ntfy(자체 서버 권장)·텔레그램·이메일 플러그인. 앱 푸시는 Phase 5 |
| 자금 관리 범위 | 납부일·금액 추적까지. 잔액·가계부는 범위 밖 |
